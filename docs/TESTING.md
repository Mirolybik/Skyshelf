# Проверки SkyShelf Final 1.0

Дата финального технического прогона: **26 сентября 2026 года**. Проверки выполнялись на JDK 17.0.20 и Node.js 24 в изолированных временных каталогах; пользовательская папка `backend/data` не изменялась.

## Подтверждённый результат

Исходники backend скомпилированы в 66 классов и упакованы в исполняемый Spring Boot JAR. Manifest содержит `Implementation-Version: 1.0.0`. Синтаксическая проверка прошла для `frontend/app.js`, `tests/http-smoke.cjs` и `tests/browser-smoke.cjs`.

Команда:

```powershell
node tests/http-smoke.cjs
```

Результат:

```text
PASS Final 1.0: proxy/CSP, CSRF sessions, encrypted objects, checksums,
versions/restore, favorites, project checklist/final/submission/ZIP,
protected one-use links, TOTP 2FA, audit, roles, trash, admin privacy,
tariff and backup/restore.
```

## Интеграционный набор JUnit

`backend/src/test/java/ru/skyshelf/AcceptanceTest.java` содержит 21 тестовый сценарий:

- guest/admin access и CSRF;
- регистрация, сессия и logout;
- файловый lifecycle;
- private/project role isolation;
- expiry/revoke/blocking ссылок;
- AES-GCM и проверка целостности;
- версии;
- защищённая ссылка и лимит;
- checklist/final/teacher submission;
- TOTP;
- admin plans;
- опасные имена, сигнатуры и расширения;
- foreign folder/workspace;
- лимит участников;
- две гонки квоты;
- учёт корзины;
- throttling плохих входов.

В текущем рабочем окружении Maven отсутствовал, поэтому обновлённый набор из 21 JUnit-теста здесь **не запускался командой `mvn test`**. Производственные исходники скомпилированы напрямую против зависимостей готового JAR, а основные новые сценарии подтверждены отдельным HTTP smoke. На компьютере команды перед сдачей обязательно выполнить:

```powershell
cd backend
mvn clean test
```

Предыдущая версия проекта до расширения успешно проходила 16 Maven-тестов; это не подменяет повторный прогон текущих 21.

## Настоящий браузер

`tests/browser-smoke.cjs` подготовлен для Playwright и проверяет desktop/mobile, реальные клики, скачивание, ссылку, корзину, роли, тему, admin и перезапуск backend. В текущем окружении Chromium не удалось установить из-за ограничения загрузки браузерного бинарника, поэтому визуальный прогон не объявляется выполненным.

На Windows команды:

```powershell
npm install --no-save playwright
npx playwright install chromium
node tests/browser-smoke.cjs
```

После прогона проверить:

- папку `docs/screenshots`;
- отсутствие `pageerror` и ошибок console;
- ширину 1440 и мобильный viewport 390 × 844;
- landing после полной прокрутки;
- модальные окна версий, ссылок, 2FA и участников;
- публичные страницы в приватном контексте.

## Ещё не подтверждено

- `start.bat` на конкретных компьютерах команды;
- Docker Compose с PostgreSQL и MinIO;
- согласованный backup/restore PostgreSQL + MinIO;
- публичный HTTPS-стенд;
- production rate limiting за reverse proxy;
- антивирусная проверка;
- нагрузка и большие объёмы;
- независимый security review/pentest;
- пользовательские тесты 3–5 студентов.

Эти пункты внесены в [PLAN.md](PLAN.md) и не выдаются за завершённые.

## Ручной security-check перед защитой

1. Убедиться, что `.env` и `backend/data` не попали в репозиторий/архив сдачи с личными данными.
2. Проверить, что cloud key отличается от учебного локального ключа.
3. Не публиковать демо-аккаунты на внешнем стенде.
4. Открыть protected link с неверным паролем и после лимита.
5. Войти READER и проверить отсутствие кнопок записи плюс прямой 403 на изменение.
6. Убедиться, что ADMIN без членства получает 404 при скачивании чужого файла.
7. Остановить сервер, сделать копию, восстановить в другой каталог и сравнить скачанные байты.
